# Мессенджер с шифрованием

Учебный клиент-серверный проект по ТЗ АИС МШ. Сервер написан на Python, база данных — PostgreSQL, клиент — обычные HTML, CSS и JavaScript без сборщика и фреймворка. По структуре проект близок к примеру ElectronicNotebook: интерфейс, API, работа с БД и тесты. Микросервисов, Redis и очередей нет.

JavaScript нужен для шифрования **в браузере**: если шифровать сообщения на сервере Python, сервер будет знать исходный текст, что противоречит ТЗ.

## Открыть запущенный проект

[https://localhost:8443](https://localhost:8443)

Для локального учебного запуска используется самоподписанный TLS-сертификат. В Chrome откройте «Дополнительные» → «Перейти на сайт localhost». Сертификат хранится в Docker volume и не меняется при обычном перезапуске. Доступ снаружи компьютера по умолчанию закрыт.

В подготовленной демонстрационной базе:

| Логин | Пароль входа | Секретная фраза переписки |
|---|---|---|
| admin | StudyAdmin2026 | Секретная фраза администратора 2026 |
| alice | StudyAlice2026 | Секретная фраза Алисы 2026 |
| bob | StudyBob2026 | Секретная фраза Бориса 2026 |

Это открыто опубликованные учебные реквизиты, только для демонстрации. Для личной переписки создавайте новые учётные записи и собственные секретные фразы.

Для содержательной демонстрации войдите как **`demo_anna`**: пароль **`DemoPass2026`**, секретная фраза **`Демонстрационная фраза 2026`**. У Анны доступны 4 личных диалога и 3 группы с подготовленной перепиской и файлами.

## Запуск на другом компьютере

Нужен Docker Desktop с Linux containers. Python и PostgreSQL на Windows устанавливать не требуется.

В PowerShell из каталога `messenger`:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1
```

Скрипт создаст `.env` со случайными паролем БД и JWT-секретом и выполнит `docker compose up -d --build`. В новой пустой БД будет только `admin / StudyAdmin2026`; секретную фразу для него вы зададите при первом входе. Алиса, Борис и примеры переписки появятся после восстановления прилагаемого `backups/demo.dump`:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\restore.ps1 -BackupFile demo.dump
```

Восстановление заменяет текущее содержимое БД содержимым выбранной копии. Выполняйте его только для нужного учебного экземпляра.

Для запуска без PowerShell создайте `.env` с `DB_PASSWORD`, `JWT_SECRET` (случайные строки) и `ADMIN_PASSWORD` (от 8 символов, буквы и цифры), затем выполните `docker compose up -d --build`.

## Возможности

- Вход по логину и паролю; блокировка на 5 минут после трёх ошибок.
- Поиск пользователей по имени и логину, личные чаты.
- Группы до 10 участников, приглашение, исключение, назначение администраторов группы.
- Текст до 5000 символов, файлы до 8 МБ, ответы на сообщения, удаление своих сообщений для всех.
- Статусы отправки, доставки, прочтения и присутствия; зашифрованная история и доставка после возвращения в сеть.
- Защита от дубликатов при повторе запроса; три повтора после первой неудачной попытки.
- Вход с другого устройства с той же секретной фразой.
- Создание и изменение пользователей, блокировка, удаление, отзыв сеансов, сброс пароля, журнал аудита.
- Резервные копии PostgreSQL вручную и автоматически раз в неделю; файлы хранятся внутри зашифрованных записей БД.

## Устройство проекта

```text
app/
  main.py             API и проверки бизнес-правил
  db.py               соединения PostgreSQL и транзакции
  schema.sql          таблицы и связи
  security.py         пароли, JWT и роли
  static/
    index.html        формы и главное окно
    style.css         оформление и мобильная версия
    app.js            обработчики интерфейса и запросы API
    crypto.js         клиентское шифрование
    history.js        зашифрованный кеш IndexedDB
scripts/              запуск, резервирование, тесты
tests/                интеграционные и браузерные проверки
docs/                 четыре руководства и результаты проверок
compose.yaml          приложение, PostgreSQL, недельное резервирование
Dockerfile            образ Python-приложения
```

Сервис `backup` — небольшой цикл `pg_dump`, использующий тот же образ PostgreSQL. Он не участвует в обмене сообщениями. Основных компонентов два: приложение и БД.

## Повседневные команды

```powershell
docker compose ps                    # состояние контейнеров
docker compose logs --tail 50 app     # журнал сервера
docker compose stop                  # остановить с сохранением БД
docker compose up -d                  # снова запустить
powershell -ExecutionPolicy Bypass -File .\scripts\backup.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\test.ps1
```

Обычные остановка, пересоздание контейнера и `docker compose down` сохраняют данные в volume `study-messenger_postgres_data`. Команда `docker compose down -v` удаляет этот volume вместе с базой — для обычного завершения работы она не нужна.

Для простоты интерфейс опрашивает сервер примерно раз в секунду. Это учебная реализация E2EE, без Double Ratchet и прямой секретности. Подмена клиентского кода скомпрометированным сервером не входит в модель защиты. Названия групп, состав участников, время и размеры пакетов не скрываются. Само содержимое текста, имена и содержимое вложений шифруются в браузере.

Полные 24 часа непрерывного испытания и месячная доступность не подтверждены краткими проверками. Это отдельно отмечено в ведомости испытаний; проект не выдается за прошедшую промышленную приемку систему.
