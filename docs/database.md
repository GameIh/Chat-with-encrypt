# Руководство администратора базы данных

## Хранение

PostgreSQL 16 работает в сервисе `db`, база и пользователь называются `messenger`. Пароль берётся из `.env`. Данные находятся в volume `study-messenger_postgres_data`; файлы сообщений хранятся внутри поля `messages.payload` как зашифрованный пакет, поэтому отдельного файлового хранилища нет.

Таблицы: `users` (пользователи, хеши, открытые ключи и зашифрованные контейнеры закрытых ключей), `sessions` (отзываемые сеансы), `chats`, `members`, `messages`, `receipts`, `audit`. Схема находится в `app/schema.sql`. Связи заданы внешними ключами; сообщения индексированы по чату и времени.

При запуске создаются отсутствующие таблицы. Изменения существующей схемы нужно оформлять отдельным SQL-скриптом и применять после резервирования — автоматических миграций в учебной версии нет.

## Резервирование

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\backup.ps1
```

Скрипт запускает `pg_dump -Fc` внутри контейнера и записывает согласованную копию в `backups/messenger-ДАТА-ВРЕМЯ.dump`. Двоичный поток не проходит через перенаправление PowerShell, которое могло бы повредить файл.

Сервис `backup` делает копию при запуске после готовности приложения и затем каждые 604800 секунд (7 дней). Если выгрузка не удалась, повторяет через час. Готовая копия переименовывается из `.tmp` только после успешного `pg_dump`. Проверяйте `docker compose logs backup`, свободное место и появление файлов. Автоудаления старых копий нет. Храните хотя бы одну копию на другом носителе.

Копия содержит хеши паролей и метаданные пользователей, поэтому ограничивайте доступ к ней, хотя содержимое переписки в ней зашифровано. Дополнительно сохраняйте `.env` отдельно от общедоступных исходников. TLS-сертификат можно создать заново, но браузер снова попросит подтвердить его.

## Восстановление

Скопируйте нужный `.dump` в `backups` и выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\restore.ps1 -BackupFile demo.dump
```

Скрипт проверяет читаемость архива, останавливает приложение, выполняет `pg_restore --clean --if-exists --single-transaction`, затем запускает приложение. Восстановление **заменяет текущие данные**; сначала сохраните их отдельной копией. При ошибке восстановления транзакция откатывается. После возврата проверьте вход и расшифрование переписки известной секретной фразой.

Для проверки копии без замены рабочей БД создайте отдельную БД, восстановите в неё и сравните количества строк и контрольные суммы зашифрованных пакетов. Такой сценарий выполнен при проверке поставки.

При обычном аварийном завершении PostgreSQL восстанавливает подтверждённые транзакции с использованием WAL. `docker compose restart` не удаляет volume. Время восстановления большой базы зависит от объёма; полученный результат для небольшой демонстрационной базы не является гарантией часа для любого объёма.
