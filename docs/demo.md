# Демонстрационные данные

Набор добавляется к существующим данным. Он содержит 5 активных пользователей, одну заблокированную учётную запись, 4 личных диалога, 3 групповых чата и 53 сообщения, включая одно удалённое. В сообщениях приложены 4 файла: план демонстрации в двух чатах, таблица проверок CSV и схема обмена SVG.

## Вход

Для всех пяти учебных пользователей:

- Пароль: `DemoPass2026`.
- Секретная фраза: `Демонстрационная фраза 2026`.

| Логин | Имя | Что показать |
|---|---|---|
| demo_anna | Анна Смирнова | Все 7 новых чатов; администратор двух групп |
| demo_mikhail | Михаил Орлов | Личная переписка с Анной; второй администратор «Разработка мессенджера» |
| demo_elena | Елена Волкова | Передача схемы в SVG и ответы |
| demo_dmitry | Дмитрий Соколов | Личный диалог об эксплуатации и резервировании |
| demo_olga | Ольга Кузнецова | Обычный участник групп |

Запись `demo_archive` («Архивный Пользователь») заблокирована. Она нужна для показа блокировки и разблокировки в панели администратора; ключей переписки у неё пока нет. После разблокировки пароль — `DemoPass2026`, при первом входе потребуется создать секретную фразу.

Ранее созданные `admin`, `alice`, `bob` и их переписка сохраняются. Данные администратора указаны в README. Он включён в три новые группы и личный диалог с Анной, поэтому новые данные доступны и при входе под `admin`.

## Сценарий показа

1. Войдите как `demo_anna`. Откройте Михаила Орлова: в диалоге есть обычные сообщения, ответ на выбранное сообщение и CSV-файл. Скачайте вложение.
2. В другом профиле браузера войдите как `demo_mikhail`. Отправьте Анне новое сообщение; покажите обновление переписки и статусов.
3. Откройте «Разработка мессенджера» → «Участники». Анна и Михаил — администраторы группы, остальные участники имеют обычные права.
4. Откройте «Подготовка к защите». Здесь есть отметка «Сообщение удалено» и файл «План демонстрации.txt».
5. В личном чате с Еленой скачайте «Схема обмена.svg». Имя и содержимое вложения передаются в зашифрованном пакете.
6. Войдите как `admin`, откройте «Управление». Найдите заблокированного `demo_archive`, покажите доступные действия и журнал создания пользователей/ключей.

Отметки «Отправлено», «Доставлено» и «Прочитано» зависят от действий участников. После открытия чатов подготовленные статусы могут обновиться — это штатная работа программы. Скрипт не подделывает постоянное присутствие: пользователь отображается в сети только при реальных запросах клиента.

## Повторное заполнение

```powershell
docker compose exec -T app python -m scripts.seed_demo
```

Скрипт использует текущий `ADMIN_PASSWORD` из окружения контейнера. Перед запуском администратор должен хотя бы один раз войти через браузер и создать свой ключ. Если пароль администратора был изменён через интерфейс, для запуска передайте актуальный пароль через окружение команды.

Клиентский скрипт шифрует данные AES-GCM и RSA-OAEP в том же формате, что браузер. API получает только шифротекст; открытая учебная переписка присутствует в исходнике генератора намеренно. Это фикстуры для демонстрации, их нельзя считать секретными данными.

UUID сообщений фиксированы для данного сценария и чата. Повторный запуск не дублирует существующие сообщения, не восстанавливает удалённые и не сбрасывает пароли или ключи. Если учебная учётная запись была заблокирована или удалена вручную, скрипт остановится с пояснением, сохранив её состояние. В уже изменённом пользователем составе группы может создаться отдельный чат с исходным учебным составом.

Для переноса подготовленного экземпляра используйте `backups/demo.dump` по инструкции README. Восстановление снимка заменяет текущую БД; генератор, напротив, только добавляет отсутствующие учебные данные.
