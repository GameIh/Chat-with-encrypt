# Руководство по расширению проекта

## Архитектура

Браузер получает статические файлы от FastAPI и обращается к `/api`. Сервер проверяет JWT, существование сеанса, блокировку пользователя и принадлежность к чату. Доступ к PostgreSQL идёт через psycopg; SQL параметризован. Один запрос использует одно соединение и транзакцию. Асинхронный семафор ограничивает число соединений до 20, не блокируя пул потоков обработчиков при большом количестве ожидающих запросов.

Приложение использует простой HTTP polling с интервалом примерно 1 секунда после окончания предыдущего цикла. WebSocket, брокер и отдельный frontend build не требуются. Список чатов и открытая переписка обновляются автоматически, для остальных чатов отправляются подтверждения доставки.

## Шифрование

1. Браузер создаёт RSA-OAEP 2048 / SHA-256 пару ключей.
2. Из отдельной секретной фразы получает AES-256 ключ через PBKDF2-SHA-256, 600000 итераций, случайная соль 16 байт.
3. Закрытый ключ шифруется AES-GCM со случайным IV 12 байт; сервер получает только этот контейнер и открытый ключ.
4. Для каждого сообщения создаётся новый случайный AES-256 ключ. Текст, имя и содержимое вложения шифруются одним AES-GCM пакетом.
5. Ключ сообщения шифруется RSA-OAEP отдельно для каждого участника, включая отправителя. Связка chat/id/sender/reply включена в дополнительные аутентифицируемые данные AES-GCM.
6. Получатель расшифровывает ключ своим закрытым ключом, затем открывает пакет. Проверка GCM обнаруживает изменение шифротекста.

Пароль входа не используется как ключ переписки. Его PBKDF2-хеш с индивидуальной солью хранится на сервере. JWT подписывается отдельным случайным секретом из `.env`; срок — 8 часов. Для немедленного отзыва проверяются таблица сеансов и версия токенов пользователя.

Сервер ограничивает размер шифротекста и проверяет адресатов, но не может независимо проверить число символов внутри зашифрованного сообщения. Лимит 5000 символов проверяется клиентом. Контакты и метаданные не шифруются. Полноценная защита от злонамеренной подмены JavaScript самим сервером, цифровые подписи сообщений и Double Ratchet в эту учебную реализацию не входят.

## Основные API

| Операция | Путь |
|---|---|
| Вход, выход, текущий пользователь | POST `/api/login`, POST `/api/logout`, GET `/api/me` |
| Создание контейнера ключа | PUT `/api/keys` |
| Контакты | GET `/api/users?q=...` |
| Список и создание чатов | GET/POST `/api/chats` |
| Участники | POST `/api/chats/{id}/members` |
| История и отправка | GET/POST `/api/chats/{id}/messages` |
| Доставка и прочтение | POST `/api/chats/{id}/receipts` |
| Удаление своего сообщения | DELETE `/api/messages/{uuid}` |
| Пользователи и действия администратора | `/api/admin/users`, `/api/admin/users/{id}`, `/api/admin/users/{id}/action` |
| Аудит | GET `/api/admin/audit` |

Все рабочие запросы требуют `Authorization: Bearer JWT`. Пакет сообщения содержит UUID, версию состава группы, шифротекст, IV, зашифрованные ключи участников и необязательный UUID исходного сообщения. UUID обеспечивает идемпотентность повторной отправки. При изменении состава группы повышается `revision`; устаревший пакет отклоняется.

## Добавление функции

Добавьте модель запроса и маршрут в `main.py`. Для обычной функции используйте зависимость `current_user`, для административной — `administrator`. Для работы с чатом обязательно вызывайте `member_of`; не доверяйте скрытой кнопке интерфейса. Затем добавьте обработчик в `static/app.js` и элементы формы в `index.html`. Обрабатывайте пользовательский текст через `textContent`, а не `innerHTML`.

При новой структуре данных обновите SQL и документируйте миграцию. Не изменяйте формат криптографического пакета без версии и сценария совместимости. Добавьте тест доступа другого пользователя и тест основного сценария. После изменения пересоберите образ: `docker compose up -d --build`.

Тесты `tests/test_api.py` используют отдельную БД `messenger_test`; скрипт запуска отказывается от рабочей базы. `tests/browser.cjs` проверяет пользовательский путь через Chrome и создает демонстрационные alice/bob на локальном экземпляре. Для его запуска нужен Node.js, пакет Playwright и Chrome. Нагрузочный скрипт использует отдельную тестовую БД.

Справочные первоисточники: [Web Crypto API](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto), [RSA-OAEP и AES-GCM](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/encrypt), [FastAPI в Docker](https://fastapi.tiangolo.com/deployment/docker/).
